# Monday Brief — 31. August 2026

## Die Entscheidung

Wir schlagen keinen neuen Agenten-Stack vor. Wir schlagen einen begrenzten Weg vor, Agentenarbeit zuerst prüfbar zu machen: AAA Code als offene no-runtime Doctrine, FYN Assurance als geplante begleitete Kontrolllinie und FYN Academy als praktische Qualifizierung.

FYN Assurance ist dabei ausdrücklich ein Arbeitsname. Vor Marktverwendung braucht er eine professionelle markenrechtliche Ähnlichkeitsrecherche. AAA Code bleibt der Name des bestehenden Open-Source-Pakets.

## Warum jetzt

Die relevante Frage ist nicht, ob ein Modell beeindruckende Antworten schreibt. Sie lautet: Wer hat den Auftrag begrenzt, welche Daten waren erlaubt, welche Evidenz wurde tatsächlich erhoben, wer durfte entscheiden und was bleibt offen?

AAA Code adressiert die Entstehungsseite: erst Bedarf, bestehender Owner und native Fähigkeit prüfen; erst danach neue Mechanik bauen. Das Paket bleibt ohne Runtime und behauptet deshalb keine technische Durchsetzung.

## Das Angebot

Ein Sechs-Wochen-Pilot macht diese Fragen an einem abgegrenzten Engineering-Workflow sichtbar. Er liefert keinen allgemeinen Freifahrtschein, sondern ein Entscheidungsbild: Scope, Nachweise, Ausnahmen, Restlücken und ein klarer nächster Schritt oder ein bewusster Stopp.

Parallel schafft FYN Academy ein gemeinsames Arbeitsvokabular für Führung, Engineering, Risiko und interne Prüffunktionen. Die Credentials bestätigen nur definierte Praxisarbeit, keine regulatorische Befugnis.

## Das Kontrollmodell

Der Ablauf ist bewusst einfach: Contract Gate, Runtime Readiness, Worker-Arbeit, unabhängige Prüfung, Controller-Entscheidung und ein menschliches Gate. Für wesentliche Entscheidungen ist ein blinder Gegencheck mit modellfamiliengetrennten Prüfarmaturen als Anforderung beschreibbar; die Verfügbarkeit eines solchen Verfahrens wird nicht vorausgesetzt.

## Datenschutz und Regulierung

PII- und Secret-Scrubbing können technische Risiken mindern, ersetzen aber keine DPIA, keine Rechtsgrundlage und keine organisatorische Kontrolle. AI Act, DORA und Mitbestimmung werden als konkrete Prüfpfade behandelt, nicht als Marketingetikett.

## Nächster Schritt

Wir entscheiden, ob ein begrenzter Pilot charterfähig ist: ein Scope, eine Datenklasse, ein verantwortliches Team, eine Nachweisfrage und ein Stop-Kriterium. Erst dann wird über Architektur, Adapter oder Skalierung gesprochen.
